# Phase 07.1 Plan 03: in-memory graph_cache + graph_query MCP tool — Summary

**One-liner:** stock-mcp now ships a lazy-loaded `networkx.DiGraph` cache over
`vault/graph/<latest>/graph.json` and a `graph_query(bfs|community|god_nodes)`
MCP tool — automated benchmark proves 2-hop in-memory BFS is ~211× faster than
the SQL recursive CTE on a 100-node fixture (0.22ms vs 46.53ms median, N=30).

## What Shipped

### `src/stock_mcp/graph_cache.py` (203 lines)

- `GraphCache(vault_graph_dir, *, ttl_seconds)` — picks the lexicographically
  latest dated subdir under `vault/graph/`, lazy-loads its `graph.json` into a
  `networkx.DiGraph` on first `.get()` call.
- TTL-based invalidation. After expiry, re-stat's `graph.json`; reloads only
  when `mtime` actually changed (skips re-parse on stable files).
- Tolerates both `{"links": [...]}` and `{"edges": [...]}` JSON envelopes plus
  `src`/`dst` aliases (legacy writers).
- Threat-mitigations: `> 50_000` nodes triggers a structured warning log
  (T-7.1-03-04 DoS observability).
- `get_graph_cache()` singleton + `reset_graph_cache_singleton_for_tests()`
  helper.

### `src/stock_mcp/tools/graph_query.py` (215 lines)

| Mode         | Args                  | Purpose                                                       |
| ------------ | --------------------- | ------------------------------------------------------------- |
| `bfs`        | `start_id`, `depth≤5` | up-to-`depth`-hop reachable neighbors (200-node response cap) |
| `community`  | `node_id`             | community label + members (graphify attr → connected-component fallback) |
| `god_nodes`  | `top_k≤50`            | top-k highest-degree nodes (centrality proxy)                 |

- Every error path → `to_error_response`, never raises (D-21).
- `truncation_applied[]` surfaces depth/node clamps so callers see when DoS
  caps engage.

### `src/stock_mcp/models.py` (+`GraphNode`, `GraphCommunity`, `GraphQueryResult`)

```python

    truncation_applied: list[str] = []
```

All extra=`forbid`, immutable Pydantic models — no dict smuggling.

### `src/stock_mcp/server.py`

Side-effect import added so the FastMCP singleton registers `graph_query`
alongside the existing eight Phase 6 tools.

## Deviations from Plan

**1. [Rule 1 — Bug] networkx >= 3.4 default `edges` key changed**
- **Found during:** Task 1 RED→GREEN
- **Issue:** Plan sketch passed `node_link_graph(data, directed=True,
  multigraph=False)` without specifying `edges=`. networkx ≥ 3.4 deprecated
  the default `links` key in favor of `edges`, raising `KeyError: 'edges'`
  on graphify v0.7.5 output that uses `links`.
- **Fix:** Normalize both shapes to `{"links": [...]}` upstream and pass
  `edges="links"` explicitly to `node_link_graph`. Added test_handles_link_or_edges_key
  to lock both shapes.
- **Files modified:** `src/stock_mcp/graph_cache.py`,
  `tests/stock_mcp/test_graph_cache.py`
- **Commit:** `d571806`

**2. [Rule 2 — Critical functionality] Extra "bfs missing start_id" guard test**
- **Plan called for:** 7 tests covering the original bullets.
- **Adjustment:** Added an 8th test
  (`test_bfs_missing_start_id_returns_error`) so the
  "INTERNAL when required arg missing" path has explicit coverage. Plan's
  Test 7 covered "unknown mode" but the symmetric "missing start_id" path is
  the more common caller mistake.

**3. [Worktree-only] uv venv vs main repo editable install**
- **Found during:** Task 1 setup
- **Issue:** Worktree's `uv sync` in pytest produced a fresh venv missing
  dev deps; meanwhile, the repo's editable install resolves to main repo's
  `src/`. Direct `python -c` outside pytest sees the main repo source.
- **Resolution:** Tests run via `/mnt/c/Users/minsu/workspace/stock/.venv/bin/python3 -m pytest`
  with worktree as cwd — `pythonpath = ["src"]` from `pyproject.toml`
  prepends the worktree's `src/`, so test runs see the new modules. No code
  change needed; documented for future agents.
