<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| store.py params (card_id, corp_code, reason) → SQL | Identifiers and the invalidation reason cross into SQL execution. This is the SQL-injection / escape-hatch boundary. |
| DecisionCard ↔ JSONB payload | Pydantic dict serialized to JSONB and reconstructed; malformed JSON or datetime mishandling can corrupt stored cards. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-07 | Tampering | SQL injection via `card_id` / `corp_code` / `reason` | mitigate | All `store.py` SQL uses SQLAlchemy `text()` + bind params (mirror krx/db_writer.py); never f-string interpolate (RULES Safety / ASVS V5). `reason` goes through `to_jsonb(:reason)` bind. |
| T-02-08 | Elevation of Privilege | arbitrary-SQL escape hatch | mitigate | Veto #7: `store.py` exposes ONLY the four typed helpers — no generic `run_sql`/query function. Acceptance criterion greps for absence of f-string SQL. |
| T-02-09 | Tampering | non-atomic supersession leaving a dangling chain (crash between INSERT and UPDATE) | mitigate | Single `with engine.begin()` block for INSERT-new + UPDATE-old; commit-or-rollback is all-or-nothing. `AND status='active'` guard prevents clobbering an already-invalidated prior card. (Discretion #2) |
| T-02-10 | Tampering | JSONB injection / datetime corruption in payload | mitigate | psycopg3 parameterized JSONB binding; `model_dump(mode="json")` emits ISO-8601 before bind (Pitfall #3); Pydantic shape-validated the card before it reached store.py (Plan 02). |
| T-02-SC | Tampering | npm/pip/cargo installs | accept | Phase 2 installs NO new packages — all deps pinned in uv.lock (RESEARCH Package Legitimacy Audit: N/A). No slopcheck surface. |
</threat_model>
