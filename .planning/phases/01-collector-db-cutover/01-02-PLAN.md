<objective>
Strip the `--vault-root` CLI argument and the `vault_root: Path` parameter
from every collector entrypoint. This is a **signature-only refactor**: collector
bodies still write Markdown via their existing `writer.py` modules. The DB
writes come in Wave 1/2 (01-03 ... 01-07).

This plan exists because (a) Wave 1/2 plans MUST be able to call collectors
with the new keyword-only signature `(*, engine, since=None, ...)` and
(b) `_dispatch()` tests in `tests/test_cli_collect_all.py` will assert the
new kwargs shape after this plan lands.

Without this plan, Wave 1/2 plans would each need to remove `vault_root` from
the same shared files (`cli/commands.py`, `cli/__main__.py`,
`tests/collectors/conftest.py`) — that's a file-ownership conflict. Landing
this in Wave 0 makes Wave 1/2 plans truly disjoint.

The collectors' internal `writer.write_*` calls receive a placeholder
`Path(".") / "vault"` literal so they still produce files; Wave 1/2 deletes
those call sites entirely.

Purpose: SC-4 directly. SC-5 prerequisite (tests can no longer accept
`--vault-root`).

Output:
- CLI parser without `--vault-root`
- Collector signatures matching `(*, engine, since=None, ...)` keyword-only,
  no Path parameter
- `tests/test_cli_collect_all.py` updated to reflect the new kwargs shape
  in the `_dispatch` monkeypatch fake
- `tests/collectors/conftest.py::vault_tmp` retained (Wave 1/2 may still
  use it for the legacy writer call path until 01-09 deletes the writers)
</objective>
