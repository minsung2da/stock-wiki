<objective>
Cut the DART collector from `vault/raw/dart/YYYY/{rcept_no}_{corp_code}.md`
writes to direct UPSERTs into the `filings` Postgres table.

DART is the **largest body** collector — full 사업보고서 can be MB-scale text.
Hard Veto #8 means the whole body is stored in `filings.body_md TEXT NOT NULL`
with **no pre-chunking**. The `chunks` table from migration 0002 is NOT touched
(Phase 3 may rebuild a narrative-search layer atop a different schema).

`body_tsv` and `body_embedding` stay NULL — Phase 3 populates them. Phase 1
does not import `sentence-transformers` or `mecab-ko`.

Bug C (Phase 4 historical fix) is preserved: when at least one filing
successfully writes, `upsert_entity(engine, corp_code, name, ticker)` is
called once at end of run so downstream `resolve_entity(ticker)` succeeds for
this corp.

Purpose:
- SC-1 (DART INSERTs into `filings`, no `vault/raw/`)
- SC-2 (UPSERT dedup on `rcept_no`)
- SC-5 (DB-based tests for `tests/collectors/dart/`, which did not previously
  exist — this plan creates the directory)

Output:
- `src/collectors/dart/db_writer.py`
- `collect_dart` body wired to db_writer
- New test directory `tests/collectors/dart/` with `test_collect_dart.py`
  and `test_db_writer.py`
</objective>

    ```python
    def upsert_dart_filing(
        engine: Engine,
        *,
        rcept_no: str,           # 14 ASCII digits
        corp_code: str,          # 8 ASCII digits (must exist in entities)
        ticker: str | None,      # 6 ASCII digits or None (per Pitfall 7)
        filed_at: datetime,      # TIMESTAMPTZ; KST close 15:30 if only date known
        report_nm: str,
        pblntf_ty: str,          # 'A' or 'B' (DART regular); CHECK at app level
        body_md: str,            # WHOLE filing text — Veto #8
        source_url: str,
    ) -> Literal["inserted", "updated", "skipped"]:
        """UPSERT on rcept_no. body_md stored verbatim (no chunking).

        event_type is left NULL for DART A/B filings. KIND (01-05) sets it
        for pblntf_ty='I' filings via upsert_kind_filing.
        """
    ```

    Implementation:

    1. Validate `rcept_no` is 14 ASCII digits, `corp_code` is 8 ASCII digits,
       `pblntf_ty in {'A','B'}`, `ticker` is 6 ASCII digits or None.

    2. Compute `content_hash = sha256(normalize_body(body_md)).hexdigest()`.

    3. Load-then-classify (same pattern as 01-05):
       ```python
       with engine.begin() as conn:
           existing = conn.execute(
               text("SELECT content_hash FROM filings WHERE rcept_no=:r"),
               {"r": rcept_no},
           ).scalar()
           if existing is None:
               outcome = "inserted"
           elif existing != content_hash:
               outcome = "updated"
           else:
               conn.execute(
                   text("UPDATE filings SET last_seen_at=now() WHERE rcept_no=:r"),
                   {"r": rcept_no},
               )
               return "skipped"
           conn.execute(upsert_sql, params)
       return outcome
       ```

    4. UPSERT SQL:
       ```sql
       INSERT INTO filings
         (rcept_no, corp_code, ticker, filed_at, report_nm, pblntf_ty,
          event_type, source_url, content_hash, body_md, fetched_at)
       VALUES
         (:rcept_no, :corp_code, :ticker, :filed_at, :report_nm, :pblntf_ty,
          NULL, :source_url, :content_hash, :body_md, now())
       ON CONFLICT (rcept_no) DO UPDATE SET
         body_md = EXCLUDED.body_md,
         content_hash = EXCLUDED.content_hash,
         report_nm = EXCLUDED.report_nm,
         ticker = COALESCE(EXCLUDED.ticker, filings.ticker),
         last_seen_at = now()
       ```
       Note: `event_type = NULL` is HARD-CODED for the DART branch — KIND
       sets it via a different db_writer in 01-05. If 01-05 (kind) and
       01-07 (dart) both happen to UPSERT the same rcept_no (pblntf_ty='I'
       filing that DART regular happens to scan), KIND's UPSERT wins for
       event_type — but in practice DART regular's `list_ab_filings`
       filters pblntf_ty='A','B' only, so this collision is rare.
       Document the precedence in the module docstring.
