<objective>
Cut the news collector from `vault/raw/news/*.md` writes to direct UPSERTs
into the `news` Postgres table.

News is the first **body-bearing** collector. Each row carries `body_md` (the
2-paragraph cap survives), `content_hash`, and a `tickers TEXT[]` array of
all alias-matched tickers. The `body_tsv` and `body_embedding` columns stay
NULL — Phase 3 populates them.

This plan does **not** populate embeddings, **does not** run prompt-injection
defense (deferred to Phase 3 per RESEARCH.md security domain table). The
collector simply writes raw body + matched ticker list.

Purpose:
- SC-2 (UPSERT dedup for news on url_hash)
- SC-5 (DB-based test assertions for tests/collectors/news/)
- First exercise of the body_md + tickers[] write path

Output:
- `src/collectors/news/db_writer.py`
- `collect_news` body wired to db_writer
- Tests fully ported to DB assertions
</objective>

    `db_writer.upsert_news_article` contract:
    ```python
    def upsert_news_article(
        engine: Engine,
        *,
        url: str,
        outlet: str,
        published_at: datetime,
        title: str,
        body_md: str,
        tickers: list[str],     # alias-matched, non-empty
        corp_code: str | None,  # first matched ticker's corp_code, may be None
        license_flag: str = "summary_only",
    ) -> Literal["inserted", "updated", "skipped"]:
        """
        UPSERT on url_hash. Returns:
          "inserted" — new row
          "updated"  — existing row, content_hash changed (body edited)
          "skipped"  — existing row, content_hash matched (no-op, last_seen bumped)
        """
    ```

    Implementation outline:
    - Validate `tickers` is a non-empty list of 6-digit strings (or
      empty — actually the collector pre-filter ensures non-empty; but
      db_writer can accept empty for defensive code).
    - Compute:
      ```python
      url_hash = url_hash64(url)
      content_hash = hashlib.sha256(
          normalize_body(f"{title}\n{body_md}").encode("utf-8")
      ).hexdigest()
      ```
    - Load-then-classify:
      ```sql
      SELECT content_hash FROM news WHERE url_hash = :uh
      ```
      Compare with new content_hash → "inserted" / "updated" / "skipped".
      If "skipped", `UPDATE news SET last_seen_at=now() WHERE url_hash=:uh`.

    - UPSERT SQL:
      ```sql
      INSERT INTO news
        (url_hash, url, outlet, corp_code, tickers, published_at, title,
         content_hash, body_md, license_flag, fetched_at)
      VALUES
        (:url_hash, :url, :outlet, :corp_code, CAST(:tickers AS text[]),
         :published_at, :title, :content_hash, :body_md, :license_flag, now())
      ON CONFLICT (url_hash) DO UPDATE SET
        title = EXCLUDED.title,
        body_md = EXCLUDED.body_md,
        content_hash = EXCLUDED.content_hash,
        tickers = EXCLUDED.tickers,
        corp_code = EXCLUDED.corp_code,
        last_seen_at = now()
      WHERE news.content_hash IS DISTINCT FROM EXCLUDED.content_hash
      ```

    - **Pitfall #8 from RESEARCH.md (psycopg3 ARRAY binding):** binding a
      Python list to `tickers TEXT[]` via `:tickers` is tricky. Two safe
      patterns:
      (a) `CAST(:tickers AS text[])` + bind `tickers` as a list — psycopg3
          adapts the list properly when the cast is explicit.
      (b) Use SQLAlchemy Core with `postgresql.ARRAY(sa.Text)` column type
          via the ORM (`db.entity_models.News`) and insert via `conn.execute(insert_stmt, params)`.

      Prefer (a) for consistency with other db_writer modules. Confirm by
      running the test container test.
