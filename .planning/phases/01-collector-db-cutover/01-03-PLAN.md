    ```python
        engine: Engine,
        *,
        source: str,         # 'ecos' | 'fred'
        series_id: str,
        item_code: str,      # '' for FRED
        label: str,

        """
        Returns (inserted_count, updated_count, revisions).

        revisions = [{"obs_date": "YYYY-MM-DD", "old": <prev_value>, "new": <new_value>}, ...]
        — populated only when an UPDATE changed an existing value (R-06).
        """
    ```

    Implementation:

    1. Pre-flight validation:
       - `source` must be in `{'ecos', 'fred'}` (raise ValueError otherwise).
       - `series_id` must match `^[A-Z0-9_-]{1,32}$` (reuse the regex from
         `writer.py` — copy it here; do NOT import from writer.py, which
         01-09 deletes).
       - `cycle` must be in `{'D','M','Q','Y'}` (default 'D' if empty).
       - `observations` is allowed to be empty — function returns (0, 0, []).

    2. SQL: use one `INSERT ... ON CONFLICT ... DO UPDATE WHERE ...` per
       transaction (engine.begin()). Build a single multi-row INSERT with
       `executemany`-style bind list:
       ```sql
       INSERT INTO macro_series
         (source, series_id, item_code, obs_date, value, unit, label, cycle, fetched_at)
       VALUES (:source, :series_id, :item_code, :obs_date, :value, :unit, :label, :cycle, now())
       ON CONFLICT (source, series_id, item_code, obs_date) DO UPDATE
         SET value = EXCLUDED.value,
             unit  = EXCLUDED.unit,
             label = EXCLUDED.label,
             cycle = EXCLUDED.cycle,
             fetched_at = now()
         WHERE macro_series.value IS DISTINCT FROM EXCLUDED.value
       RETURNING (xmax = 0) AS inserted_flag,
                 obs_date,
                 value AS new_value,
                 (CASE WHEN xmax <> 0 THEN macro_series.value END) AS old_value
       ```
       Wait — `xmax = 0` is the Postgres trick for "this row is freshly
       inserted" (vs updated). Read `RETURNING` row-by-row to classify each
       outcome.

       ACTUALLY simpler approach: do two passes — SELECT existing rows
       first, build inserted/updated/skipped buckets in Python, then issue
       a single INSERT ... ON CONFLICT DO UPDATE. The bookkeeping is
       deterministic and the perf hit is negligible (macro series have
       hundreds of observations max).

       Pseudocode:
       ```python
       with engine.begin() as conn:
           # Step 1: load existing values for the (source, series_id, item_code) slice
           existing = {
               row.obs_date: float(row.value)
               for row in conn.execute(text("""
                   SELECT obs_date, value FROM macro_series
                   WHERE source=:s AND series_id=:sid AND item_code=:ic
               """), {"s": source, "sid": series_id, "ic": item_code})
           }
           # Step 2: classify each observation
           inserted = updated = 0
           revisions: list[dict] = []
           rows_to_upsert: list[dict] = []
           for obs in observations:
               new_value = float(obs["value"])
               obs_date = obs["date"]
               prev = existing.get(obs_date)
               if prev is None:
                   inserted += 1
                   rows_to_upsert.append({...})
               elif prev != new_value:
                   updated += 1
                   revisions.append({"obs_date": obs_date.isoformat(),
                                     "old": prev, "new": new_value})
                   rows_to_upsert.append({...})
               # else: same value, skip (no DB write)
           # Step 3: single UPSERT for inserted+updated rows
           if rows_to_upsert:
               conn.execute(text("""
                   INSERT INTO macro_series (...) VALUES (...)
                   ON CONFLICT (source, series_id, item_code, obs_date) DO UPDATE
                     SET value=EXCLUDED.value, label=EXCLUDED.label,
                         cycle=EXCLUDED.cycle, unit=EXCLUDED.unit,
                         fetched_at=now()
               """), rows_to_upsert)
       return inserted, updated, revisions
       ```
       This avoids the RETURNING/xmax trick and produces deterministic
       inserted/updated counts.

    3. Decimal vs float: `NUMERIC(20,6)` is high-precision. Bind Python
       `float` directly — psycopg3 handles the conversion. Comparison
       `prev != new_value` uses float equality, which is OK because macro
       values come from upstream APIs as floats already.
