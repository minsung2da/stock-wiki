<objective>
Cut the KIND collector from `vault/raw/kind/*.md` writes to direct DB inserts.

KIND is the first **multi-table** collector: each DART `pblntf_ty="I"` event
produces TWO rows — one in `filings` (the underlying disclosure) and one in
`events` (the KIND classifier row pointing at the filing via
`filing_rcept_no`). Pure-KIND AJAX events (no DART rcept_no) produce only a
single `events` row with `source='kind'`.

This plan tests the FK link between `events` and `filings` and establishes the
**paired-write transaction pattern** that 01-07 (dart) reuses for its more
complex body-bearing filings. The kind plan keeps `filings.body_md` minimal
(the event filing's report_nm + source_url) — Phase 1 does NOT need to fetch
the full filing body for KIND-classified events. Plan 01-07 (dart) is where
full body fetching is wired; KIND rows can be backfilled in Phase 3 if needed.

Purpose:
- SC-2 (UPSERT dedup for kind/filings/events)
- SC-5 (DB-based test assertions for tests/collectors/kind/)
- Validates the cross-table FK contract from 01-01

Output:
- `src/collectors/kind/db_writer.py` with two helpers:
  `upsert_kind_filing` and `upsert_kind_event`
- `collect_kind` body wired to db_writer
- Tests fully ported to DB assertions
</objective>

    `upsert_kind_filing` implementation:
    - Validate `rcept_no` is 14 ASCII digits.
    - Validate `event_type` in the five-value enum.
    - Compute `content_hash = sha256(normalize_body(body_md)).hexdigest()`
      (use `shared.content_hash.normalize_body`).
    - SQL:
      ```sql
      INSERT INTO filings
        (rcept_no, corp_code, ticker, filed_at, report_nm, pblntf_ty,
         event_type, source_url, content_hash, body_md, fetched_at)
      VALUES
        (:rcept_no, :corp_code, :ticker, :filed_at, :report_nm, 'I',
         :event_type, :source_url, :content_hash, :body_md, now())
      ON CONFLICT (rcept_no) DO UPDATE SET
        body_md = EXCLUDED.body_md,
        content_hash = EXCLUDED.content_hash,
        event_type = EXCLUDED.event_type,
        last_seen_at = now()
      WHERE filings.content_hash IS DISTINCT FROM EXCLUDED.content_hash
      RETURNING (xmax = 0) AS inserted_flag
      ```
      Distinguish "inserted" / "updated" / "skipped":
      - If RETURNING is non-empty: read `inserted_flag` (true=inserted,
        false=updated).
      - If RETURNING is empty (no rows changed; the WHERE filtered them
        out): "skipped". Update last_seen_at separately:
        ```sql
        UPDATE filings SET last_seen_at = now() WHERE rcept_no = :rcept_no
        ```
        Then return "skipped".

    `upsert_kind_event`:
    - Validate `event_type` in the enum.
    - Validate `source IN {'dart','kind'}`.
    - Validate `ticker` is 6 ASCII digits.
    - SQL:

      ```sql
      INSERT INTO events
        (event_type, ticker, event_date, corp_code, subtype, reason,
         source, source_id, source_url, filing_rcept_no, fetched_at)
      VALUES (...)
      ON CONFLICT (event_type, ticker, event_date, source, source_id)
        DO NOTHING
      RETURNING id
      ```
      If RETURNING has a row → "inserted"; if empty → "skipped".
