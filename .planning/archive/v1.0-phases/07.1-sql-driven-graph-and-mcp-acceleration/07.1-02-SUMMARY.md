# Phase 07.1 Plan 02: SQL-driven Snapshot Rewrite — Summary

**One-liner:** `src/graph/snapshot._run_graphify` now reads SQL via
`sql_to_graph.build_extraction(get_engine())` and feeds the result straight to
`graphify.build.build_from_json`, fully removing the `graphify.detect /
collect_files / extract` markdown-AST path that produced empty graphs in
Phase 7 (gap-1).

## What Shipped

### `src/graph/snapshot.py` rewrite

**Before (Phase 7):**
```python
from graphify.detect import detect
from graphify.extract import collect_files, extract
detection = detect(Path(input_dir))
files = collect_files(Path(input_dir))
extraction = extract(files, cache_root=Path(input_dir)) if files else {...empty...}
```
Result: empty graph on a markdown-only vault (HUMAN-UAT gap-1).

**After (Phase 7.1):**
```python
from src.graph.sql_to_graph import build_extraction
from src.db.engine import get_engine
extraction = build_extraction(get_engine())
G = build_from_json(extraction, directed=True)
```
Result: graph.json populated from `edges` + `entities` + `documents` with
the full Phase 7 edge taxonomy (mentions_ticker / note_ticker /
ticker_sector / supersedes / filing_event / event_event).

`window.build_staging` is no longer called — SQL replaces the staging
window. `window.py` itself is retained because `tests/graph/test_window.py`
exercises it as an isolated unit.

### `tests/graph/conftest.py` slim-down

`graphify_stub` fixture before:
- Stubbed 8 submodules (graphify + detect + extract + build + cluster + analyze + report + export).
- `_to_json` always wrote `{"nodes": [], "edges": []}`.

`graphify_stub` fixture after:
- Stubs 6 submodules (no detect, no extract).
- `_to_json` replays `extraction["nodes"]` / `extraction["edges"]` into
  `graph.json` so callers can assert on payload shape.
- Monkeypatches `src.graph.sql_to_graph.build_extraction` and
  `src.db.engine.get_engine` so unit tests never touch the live DB.
- New `state["extraction"]` knob lets integration tests inject real
  SQL output while keeping the rest of the pipeline mocked.

### `tests/graph/test_snapshot_integration.py` (4 tests, 207 lines)

1. **`test_snapshot_produces_non_empty_graph_json`** — gap-1 regression
   guard. Seeds edges via `seed_edges(with_event_chain=True)` + runs
   `ingest.edges.populate`, then injects the real `build_extraction(engine)`
   result via `_real_build_extraction` (importlib spec load that bypasses
   the fixture monkeypatch). After `snapshot()` runs, asserts both
   `nodes` and `links` are non-empty.
2. **`test_graph_json_link_carries_tag`** — SC-2 guard. Asserts that
   `edges.tag = "EXTRACTED"` round-trips into `graph.json` link entries.
3. **`test_snapshot_does_not_import_graphify_detect_or_extract`** — SC-4
   guard. Inserts `None` for `graphify.detect` and `graphify.extract` in
   `sys.modules`; if any residual code path still tried to import them,
   `snapshot()` would raise. PASS proves the new path is graphify.detect-free.
4. **`test_snapshot_with_real_graphify_round_trip`** — full real-graphify
   smoke. Auto-skipped when graphify is not installed (`importlib.util.find_spec`
   gate). Exercises the entire build/cluster/analyze/export pipeline against
   real SQL data — catches contract drift in graphifyy 0.7.x.

## Deviations from Plan

**1. [Rule 1 — Bug] `detection_result['total_files']` required by graphify.report.generate**
- **Found during:** Task 2 (real-graphify round-trip test surfaced the issue)
- **Issue:** Plan's snapshot rewrite passed `{"sql": "edges+entities+documents"}`
  as the detection placeholder. graphify.report.generate's "Corpus Check" branch
  reads either `detection_result['warning']` (short-circuit) or
  `detection_result['total_files']` / `total_words` — the placeholder satisfied
  neither, raising `KeyError: 'total_files'` against the real graphify pipeline.
- **Fix:** snapshot now emits a detection dict with `warning` + `total_files`
  (count of document nodes in the extraction) + `total_words=0` so the report
  renders cleanly under either branch.
- **Files modified:** `src/graph/snapshot.py`
- **Commit:** `b2c41f0`

**2. [Rule 3 — Blocking] `_load_build_extraction` collided with fixture monkeypatch**
- **Found during:** Task 2 RED phase
- **Issue:** Plan sketched a helper that did `from src.graph.sql_to_graph import
  build_extraction` inside the test, but the same fixture monkeypatched that
  symbol to a stub returning `{"nodes": [], "edges": [], ...}` — so the
  "real" extraction path resolved to the stub, leaving graph.json empty and
  failing the gap-1 assertion.
- **Fix:** Replaced with `_real_build_extraction(engine)` helper that loads
  `sql_to_graph.py` fresh via `importlib.util.spec_from_file_location`,
  bypassing the patched module in `sys.modules`. The fixture's stub stays
  active for the snapshot pipeline; only the seed step uses the real adapter.
- **Files modified:** `tests/graph/test_snapshot_integration.py`
- **Commit:** `b2c41f0`

**3. [Rule 2 — Critical functionality] Real-graphify round-trip smoke test**
- **Plan called for:** stub-only integration tests (3 tests).
- **Adjustment:** Added a 4th test (`test_snapshot_with_real_graphify_round_trip`)
  gated by `importlib.util.find_spec("graphify.detect")` so it auto-skips
  when graphify is not installed. Catches contract drift between graphifyy
  0.7.5 and our snapshot caller (e.g., the `total_files` issue above) before
  it reaches the CLI.

## Key Interfaces for Plan 03 (MCP graph_cache)

The graph.json shape is now contractual and non-empty:

```json
{
  "nodes": [
    {"id": "doc1", "type": "document", "label": "...", "source_file": "..."},
    {"id": "005930", "type": "ticker", "label": "삼성전자", "source_file": "..."}
  ],
  "links": [
    {"source": "doc1", "target": "005930",
     "edge_type": "mentions_ticker", "tag": "EXTRACTED", "weight": 1.0}
  ]
}
```

Plan 03 (MCP graph_cache) can warm a NetworkX cache from this JSON via the
same `build_extraction(engine)` adapter (per Plan 01 SUMMARY) — no need to
re-parse `graph.json`. The on-disk artifact remains the canonical
human/Obsidian view, while in-memory traversal goes straight from SQL to
NetworkX in the MCP server warm-up phase.
