Add a single shared helper `read_existing_derived(path)` in `src/shared/frontmatter.py` and call it from each collector's writer before constructing the new `FrontMatter`.

def read_existing_derived(path: Path) -> DerivedBlock | None:
    """Returns prior _derived block, or None if file absent / malformed / _derived empty.

<known_tradeoff>
## Known Tradeoff (locked by CONTEXT.md D-02 — DO NOT change)

After this fix, `walk.find_candidates` will SKIP a doc whose body genuinely changed if the carried `_derived` block is structurally still populated. Why: collector writes the new content_hash AND carries the prior `_derived` → at next walk scan, `stored == actual` (both reflect the new body) AND `_derived_is_populated(fm)` is true → skip.

This means: if a macro series gains a new observation that meaningfully shifts sentiment, the prior `_derived` will be reused unless the human or a separate doctor pass invalidates it. CONTEXT.md explicitly accepts this tradeoff: "the Routine's existing logic handles the 'content_hash changed → re-enrich' case for free; collector preservation just means the Routine has the prior enrichment to fall back on if the body is structurally similar."

This is documented here so the human reviewer is aware. **Do NOT add collector-side invalidation logic** — that would create two competing freshness gates and undo the fix's purpose.
</known_tradeoff>
